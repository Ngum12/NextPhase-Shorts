## A. Product charter and immutable design rules

1. **Shorts only.** Output video must be vertical 9:16 and never exceed **60.00 s** in the final validated export. Allow templates 15, 30, 45 and 60 seconds, and automatically choose an optimal length <= requested cap when the narrative requires it. Later allow custom 5–60 s durations. If source video is shorter, don't fabricate speech or silently extend it.
2. **Allow long input, short output.** Start with uploaded source clips of up to 10 minutes and <=300 MiB (configurable). Future batch/long-input support only after benchmarks and cost gating. Intelligent highlight selection, not just first-N-seconds trimming, is an essential later milestone.
3. **Cloud-first execution.** **Never** run speech models, video generative models, background matting, compositing, ML inference, final FFmpeg renders, or multi-frame effects on phones. Phone tasks: capture/import, upload, authenticated preview/playback, settings, small thumbnail rendering when native OS provides it, downloads/shares. Understand that recording/uploading/playback still use battery; avoid false promises of zero heat/crashes.
4. **Original human footage matters.** Prioritize preserving a speaker's identity, face, natural voice and meaning. Never replace them with invented lookalike people or voice clones unless user-initiated, consented and legally supported. No random/irrelevant B-roll.
5. **Quality over gratuitous effects.** An AI creative director selects effects only if useful; no obligatory cuts every 0.6 s or chaotic typography. Maintain aesthetic consistency, readable subtitles, preserved speech, and non-fatiguing audio.
6. **Commercial-safety license gate.** DO NOT copy any code, documentation, images, media, fonts, or sounds from the user-provided skill ZIPs into this new commercial SaaS without verified authorization. The provided `NextPhase-EditorV1.zip` specifically forbids reselling/repackaging its kit as a paid product. Reimplement lawful general concepts independently or obtain written permission. Keep a provenance/attribution register. The skill packs are reference inspiration, **not** redistributable dependencies by default.
7. **Security and privacy.** A user can only access their own projects, uploads, results and entitlements. No hardcoded API keys, no public buckets, no arbitrary process command construction, no remote shell generated by an LLM, no unsafe file/path use. Explicit privacy/retention/consent and deletion features before launch.
8. **Business economics are product requirements.** Every job records compute and AI cost; subscriptions enforce real quotas, concurrency and fair use. No unlimited production renders on unmeasured infrastructure. Paid features are server-verified; no client-side-only unlocks.
9. **Accessibility and emerging-market UX.** Test budget Android devices on slow, unstable networks; resume uploads; provide clear error states; clean English/French copy at launch, then expand through tested language support. Start with Android, design cross-platform from day one and ship iOS when billing/policy approvals permit.
10. **Truthy labels.** The supplied scaffold is only **Stage 1 baseline**: upload -> queue -> plain vertical trim/letterbox -> download. Six style names are planned but not yet implemented. Never falsely label the starter as AI editing, automatic captions, cloud hosting or a paid subscription product.

## C. System boundaries and production target

**Mobile:** Expo/React Native + TypeScript + Expo Router. Android first, iPhone next. Use OS-native picker, OS video playback, uploads/downloads, background transfer APIs where supported, secure credential storage. Prevent screen-navigation crashes; uploads must not restart from zero on intermittent connection once resumable upload phase is complete.

**API:** Python 3.12+ FastAPI, Pydantic typed validation, SQLAlchemy + Alembic, PostgreSQL, authenticated resource ownership, upload orchestration, job lifecycle, quota/entitlement checks, status/cancellation, webhooks, admin dashboard, support tools, audit trails.

**Queue:** Start with provided DB-backed worker; move to robust Redis/Arq/Celery or durable cloud queue in Phase 2. Guarantee job idempotency, retries, dead-letter states, cancellation, priority, leases, worker heartbeat and concurrency limits. ACK only on confirmed durable completion.

**Storage:** S3-compatible private buckets for originals, intermediate assets, outputs and image thumbnails; signed short-lived upload/download URLs. Files saved with UUID keys rather than arbitrary client filenames. Retention and deletion job. Local storage is only for development.

**AI creative director:** Pluggable provider adapters, initially disabled. The pipeline should support local free/open speech models and optional MiMo/Gemini/OpenRouter planning providers *with user consent and cost accounting*. Strict JSON scene plans validated against an EDL schema. AI model may describe what to do, **never** execute arbitrary shell/Python/JS. Source texts and transcripts are untrusted input.

**Rendering:** FFmpeg and legally licensed browser-based animation/compositing tools (e.g., independent 2D templates; optionally HyperFrames after license/version validation). Concurrency and GPU encoding chosen by benchmark. Stateless, isolated workers; prevent remote code execution and resource exhaustion. Reuse cached scene outputs when revising captions/branding.

**Billing:** Separate BillingService + EntitlementService. Initial `disabled` adapter; later provider adapters for compliant web/MoMo payment flows and Apple/Google in-app subscriptions. One normalized internal entitlement model, server-side settlement/receipt verification, no reliance on client-supplied success.

**Operations:** CI, immutable builds, worker observability, CPU/GPU cost tracing, user metrics, dashboards, QA gates, backups, disaster recovery, incident handling, retention policies.

## E. Video pipeline — complete future production flow

```
User selected source video(s)
  -> client metadata + consent + idempotent upload session
  -> multipart/resumable private upload to storage
  -> server MIME/magic/ffprobe checks, safety/rights metadata, limits
  -> normalized low-res analysis proxy ON CLOUD
  -> audio extraction + VAD + ASR with word timestamps + diarization if needed
  -> scene/silence/motion/face/object/subject importance detection
  -> transcript cleanup + human language + multilingual support
  -> hook/highlight candidates scored for narrative accuracy
  -> output target <=60 s, summary/EDL, brand/tone/asset rights rules
  -> choose appropriate style preset and scene modules
  -> rights-aware B-roll search, validation, attribution and caching
  -> storyboard approval (optional) with user revisions
  -> render graph: talking head, editorial cards, 2D and optional 3D scenes
  -> automatic portrait reframing / speaker-safe crop / caption safe area
  -> audio enhancement, leveling, beat-aware music ducking, tasteful SFX
  -> render per scene at exact frames, then concat/mix/color/encode
  -> automatic QA (duration, aspect, captions, black frames, audio, license)
  -> render result, thumbnail, user alert, private signed playback/download
  -> retention automation, invoicing/quotas and cost analytics
```

### E.1 Ingest

Build secure versioned endpoints, POST `upload-sessions`, parts, complete and abort; per-user quota/auth; abuse limits; resumable/retry with integrity hashes; progress. Source 10 min/300 MiB initial caps; support MP4/MOV/WebM/M4V by FFprobe rather than extension alone. Normalize rotation metadata, variable frame rates, mono/stereo, audio tracks, HDR / color tags and phone formats. Never automatically upload a person's gallery in the background.

### E.2 Analysis (cloud)

FFprobe -> normalized analysis proxy (low resolution) -> VAD (e.g. Silero VAD), Whisper/faster-whisper or other properly licensed ASR -> word-level timestamps, language and confidence -> scene cuts, faces/speakers, safety notes, audio loudness. Use source clip checksums to avoid repeated analysis, avoid storing full transcripts in general logs. Optional provider use only after privacy disclosures and user choices; free-tier data-retention/provider training policies must be checked.

### E.3 Smart highlights / content-aware edits

Rank candidate stretches by statement completeness, context fidelity, emotional hook, sentence boundaries, sound/visual quality, speaker continuity, non-redundancy and target audience. Enforce duration; allow phrase-preserving jump cuts and alternative hook selection. Avoid misleading montage edits that invert speaker meaning, and don't hallucinate names/facts. Build unit tests for one-second fragments, false-start detection, multi-speaker clips, no-speech clips and English/French accented speech.

### E.4 Creative director: structured output only

Generate a typed EDL with provenance for every scene, source ranges, transition and licensing metadata; validate with Pydantic/JSON Schema and reject unknown effect types and impossible time ranges. Version prompts and model options. Keep deterministic “no-AI / basic editor” fallback; score confidence and allow user intervention when uncertain. Guard against prompt injection from transcript or retrieved web content; never treat source media as instructions.

**Proposed EDL JSON contract (expand, validate, never accept as executable code):**

```json
{
  "schema_version": "1.0",
  "job_id": "server-uuid",
  "style": "documentary",
  "output": {"width": 1080, "height": 1920, "fps": 30, "duration_frames": 1350},
  "source_media": [{"asset_id":"source-01", "owner_id":"auth-user", "sha256":"...", "license":"user-owned"}],
  "scenes": [
    {"type":"talking_head", "start_frame":0,"end_frame":180,
     "source_asset_id":"source-01", "source_in_frame":300,
     "focal_box": [0.35,0.15,0.3,0.6],
     "caption_track_id":"captions-1", "effects":["gentle_push_in"]},
    {"type":"editorial_card", "start_frame":180,"end_frame":360,
     "asset_ids":["licensed-photo-1"], "text":"A powerful idea", "effects":["kinetic_headline"]}
  ],
  "audio_tracks": [{"type":"original_voice","asset_id":"source-01","lufs_target":-16}],
  "captions": [{"start_frame":0,"end_frame":60,"text":"Example only"}],
  "provenance": [{"asset_id":"licensed-photo-1","url":"https://example.org/asset","license":"verified","attribution":"Example"}]
}
```

This sample intentionally covers only 12 seconds of a potential 45 s edit; a **valid** finalized EDL must cover the entire declared duration contiguously without blank gaps, scene overlaps or unsupported assets. Validate all source frame indices and spans. No unsafe HTML/JS/script in generated plans. Store EDL, prompts, provider/version and source metadata for replay and audit.

### E.5 Scene modules

Implement as typed, independently testable renderers with common interfaces `{edl, assets, brand, output_spec} -> deterministic scene artifact`:

- `TalkingHeadRenderer`: automatic person-aware 9:16 cropping (face tracking), adaptive safe zones, fast-cut/highlight logic, simple color, optical-safe zoom.
- `CaptionRenderer`: exact word timestamps, normal and animated presets, WCAG-level contrast, 9:16 safe zones, punctuation, bidi and multilingual layout, editable words. Captions must not hide the face or crucial information.
- `DocumentaryRenderer`: contextual, rights-cleared real footage/images; motion, color treatments, article/document/title graphics, source/provenance approval.
- `EditorialCardRenderer`: original code-generated charts, quotes, lists, statistics, product information, branded infographics; never copy carousel kit source without licensing.
- `Motion2DRenderer`: original layered photography movement, kinetic typography, diagrams, abstract shapes, transitions, reactive audio cues; avoid fake or repetitive “AI look.”
- `Product3DRenderer` (optional premium): first use already-owned product photos and simple code shapes; never require a paid 3D generator for common renders. Enable only after benchmarking/licensing.
- `AudioDirector`: voice-first cleanup, high-pass/normalization/limiter, music bed, ducking, brief tastefully aligned SFX, loudness peaks QA. No unauthorised copyrighted songs.
- `BrandComposer`: logo overlays, intro/outro CTA (not always), font licensing, palette and positioning.
- `SceneComposer`: typed filter graph / independent renderer calls, cached frame groups, color/audio/output validation.

### E.6 Automatic QA

For every export assert: video stream present, width=1080 height=1920, no gross corruption, H.264/AAC MP4 compatible target, frame rate stable target 30, final duration **<=60.00 seconds**, captions in bounds, face/graphic safe areas, no black flashes except deliberate transition, no silence gaps (unless deliberate), audio peak/clipping bounds, sensible loudness and copyright/rights manifest. Check story meaning in human review samples. Keep QR reproducible job metadata; track QA failure reason, retry counts and fallback renders.

### E.7 Speed and cost design

The original local 40-second video reportedly required HOURS. Benchmark each part separately: upload, proxy generation, transcription, highlight selection, plan generation, B-roll licensing, animations, compositor, encode, quality checks. Record P50/P95 wall-clock and per-job cost on CPU-only and GPU. Optimize with scene-level caching, concurrency with bounded workers, hardware-encoding only when it improves *real* speed/quality, prebuilt fonts/templates, small proxies, delta re-render revisions, and CDN/object storage. Avoid full rerender when only a caption changes. No invented “20× faster” claim before measurements. Provide public estimated wait times only after real production data.

## F. Rendering / worker/queue engineering

- Upgrade DB schema with Alembic migrations before release. Design tables for users, projects, source_assets, upload_sessions, render_jobs, job_events, EDLs, render_artifacts, provider_costs, style_presets, subscriptions, entitlements, credit_ledger, payment_events, support_cases, rights_manifests, audit_logs.
- Enforce transactional job creation, idempotency keys, per-user concurrency and quotas; only one actor may claim a queued job; stale-lease recovery; no duplicate output charging. Move polling to a durable queue when metrics require it. Test worker interruptions and retried jobs.
- Workers run in containers with unprivileged user, short-lived temporary directory, CPU/RAM/time limits, no mounted cloud secrets beyond necessary scoped IAM role, minimal network egress, no arbitrary scripts from AI model output, strict URL fetch allowlist and SSRF restrictions. Avoid multi-tenant unsafe renderer state.
- Deploy API and workers separately; scale GPU workers only when in use; use cheaper CPU workers for low-intensity jobs. No paid GPUs needed for basic FFmpeg tests.
- Observability: trace ID, job ID, stage timings, transcoding speed (frames/s), peak memory, GPU utilization, retry counts, cost estimate, percent progress grounded in actual stages; Prometheus/OpenTelemetry-compatible signals; exceptions scrubbed of user content.
- Adopt object storage private access, expiring signed URLs, accurate retention policies and thumbnails/proxy caching; cleanup failed uploads, intermediate directories and abandoned multipart sessions.

## G. Provider strategy — cheap planning does not mean free rendering

**No paid keys in Stage 1.** API keys always server-side. OpenRouter and Gemini free tiers can be used for non-sensitive development tests when provider terms permit. MiMo-V2.6-Flash (OpenAI-compatible) is a good low-cost planning experiment but production API usage is charged even if available for free in a separate app/IDE. Choose model via configuration and benchmark quality/latency/price, don't choose based on brand hype. Local open ASR may avoid per-minute speech API fees but still uses cloud CPU/GPU resources.

Provider interfaces:

- `TranscriptionProvider.transcribe(media_ref, language_hint) -> word_timestamps, confidences`
- `CreativeDirectorProvider.plan(input_features, transcript, editorial_constraints) -> validated EDL`
- `AssetProvider.search(query, licenses) -> verified, downloadable assets + rights manifest`
- `SpeechEnhancer.process(audio_ref, settings) -> isolated audio artifact`
- `RenderBackend.render(edl, asset_manifest, output_spec) -> MP4 + stage metrics`
- `BillingProvider.receive_verified_event(signed_payload) -> normalized payment event`

Test provider failures, rate limits, timeouts, invalid JSON, prompt injection and deterministic fallback. Add monthly spend caps and circuit breakers. Never let the model write arbitrary Python or perform network fetches directly. Some 3D/AI generation requires paid credits; mark as optional and price accordingly.

## H. Six style definitions — each must feel genuinely different

| Preset | Editing philosophy | Visual devices | Audio | Typical use |
|---|---|---|---|---|
| **Documentary** | Fact-first, visual evidence and tension | archival-like evidence cards, source labels, purposeful B-roll, color treatments, restrained kinetic title | cinematic yet speech-readable | storytelling, history, startups |
| **Professional Vlog** | Authentic, smooth, lifestyle-friendly | smart jump cuts, reframing, gentle push-ins, natural colors and clean transitions | soft upbeat licensed music | personal creators, travel, daily life |
| **Viral Shorts/Reels** | Hook-first, brisk but not misleading | hook scoring, tight pacing, word accents, reaction cutaways, zoom-on-emphasis | rhythmic ducking and accents | social posts, tips, commentary |
| **Business/Product Ads** | Product benefits, consistency, CTA | branded title cards, clear product angles, offer summary, logo/outro | polished commercial bed | small businesses, promotions |
| **Education/Explainers** | Maximize understanding | code-created diagrams, legible definitions, key word highlighting, visual demonstrations | quieter and clearer | courses, public education |
| **Interviews/Podcasts** | Speakers and quotes first | multi-speaker shot switches if multiple sources, filler trimming, quote emphasis | transparent speech normalization | expert interviews, teaching |

Create a test suite with >=3 example recordings per style and a documented qualitative review rubric. Enforce 60-second cap for every style and output variant. Use 15/30/45/60 presets as duration constraints, not a license to pad footage. Each style needs distinct templates, EDL policies and audio rules rather than simply changing the dropdown label.

## I. Payments and revenue — robust design, NOT an early shortcut

1. Do **not** activate customer billing before legal/store review and integration tests. Stage 1 must have `BILLING_PROVIDER=disabled` and no public paid checkout.
2. Research market launch eligibility. Documentation suggests Flutterwave supports RWF Mobile Money (MTN/Airtel) and XAF Cameroon (MTN/Orange). Confirm business onboarding/KYC, collection fees, API limits, transaction verification, wallet prompts, refunds, settlement currency and taxation *in the actual company country*. Verify whether recurring MoMo debit is supported before offering auto-renewal; a customer-initiated monthly renewal may be the workable first option.
3. For apps distributed through Google Play and Apple App Store, comply with their **digital-feature subscription** and external purchase policies. Do not embed a Mobile Money checkout or external MoMo link inside a native app where prohibited. Consider a lawful web checkout/PWA and native store billing where required. Document region-specific policy approval rather than assuming exceptions.
4. Centralize entitlements and credits: Starter/Creator/Pro proposal; active subscription period, plan tier, style weights, scene credits, queue priority, monthly usage and carryover rules. Grant credits only after signed verified provider event or validated store purchase. Idempotent event deduplication and ledger adjustments; account for cancellations, expiry, refunds and chargebacks.
5. Prevent negative-unit-economics subscriptions: set conservative max output/minutes/month, source size cap, optional premium 3D costs, user project concurrency, retry budget; build staff-configurable cost controls and emergency kill switches.
6. Implement consentful invoice/receipt, renewal reminders, clear cancellation/refund policies, no dark patterns, transparent cost preview, fraud prevention. Currency conversion must not be guessed; use provider rates and accounting records.

## J. Security, rights, user trust and compliance

Implement a serious threat model: stolen login/session, abusive uploads, leaked output URLs, cloud SSRF, user-supplied malformed videos, prompt injection in transcript, zip bombs, shell injection, malicious B-roll URLs, GPU denial-of-service, payment-webhook forgery, third-party data leakage, copyright claims, spam fake testimonials. Attack surface includes FFmpeg codecs and browser rendering; patch regularly and isolate workloads.

Required controls: HTTPS/TLS, reverse proxy body size, signed/private object URLs, password resets and rate limits, log scrubbing, upload scans/media probing, max source size/duration/dimensions, account deletion and storage erasure, provider data policies, privacy/terms/DMCA-style reporting, consent to edit others' faces/voices, audit trails and admin RBAC. No hidden training of private videos on unconsented third parties.

Copyright and licensing: the product must keep asset URL, creator, permission, license type, expiration and user acknowledgement in project manifest; rights-cleared stock only, no scraping arbitrary content as if free. AI-generated images do not guarantee rights; check each provider's permitted business uses. Ask permission or use independent replacements for the three uploaded skill kits.

Quality ethic: preserve authenticity of speakers and avoid inaccurate subtitles or deceptive recutting, particularly for politics, medicine, finance, religion and public-interest videos. Provide edit confirmation and visible tool disclaimers as appropriate.
